# Один лишний скрипт убивает целый файл

## Симптом и механика

В консоли пользователя две строки, выглядящие как разные баги:

```
SyntaxError: Identifier '_srchItems' has already been declared (cookies_ui.js?v=13:1)
ReferenceError: checkAMDStatus is not defined (app.js:232)
```

Это **одна** причина. `let` / `const` / `class` на верхнем уровне живут в общей
глобальной области видимости всех классических `<script>`. Повторное объявление —
не предупреждение, а `SyntaxError` **на этапе парсинга**: браузер не выполняет
файл ЦЕЛИКОМ. Все функции этого файла исчезают, и падает уже совсем другое место.

Хуже всего, что падает оно внутри обработчика сообщений WebSocket: исключение
обрывает разбор события `init`, и интерфейс поднимается наполовину живым по
причине, которая ни на что не похожа.

`var` и `function` так не падают — поэтому файл, целиком написанный на них,
проблему маскирует.

## Как это возникло (31.07.2026)

`search.js` локально был слит в `cookies_ui.js`, локальный `index.html` перестал
его грузить, сам файл удалён. **В зеркале `github_setup/` остались оба** — и
файл, и `<script src=".../search.js">` перед `cookies_ui.js`. Все функции
`search.js` уже были в `cookies_ui.js`, то есть он был чистым балластом, который
ронял рабочий файл у **каждого** публичного пользователя. У владельца не
воспроизводилось никогда: локальное дерево было правильным.

## Второй случай: не JS, а view-фрагмент — и `Promise.all` (08.08.2026)

Тот же класс, другая дверь. `views.js` держит **захардкоженный** список из 21
`_VIEW_FILES` и грузил их через `Promise.all`. В публичном зеркале семи фрагментов
нет (`library`, `tagger`, `admin`, `bot`, `telemetry`, `guest-tokens`, `guest-prefs`)
— **одного** 404 хватало, чтобы `Promise.all` отклонился, а это был **первый
`await` в обработчике `window.load`** в `app.py`… то есть в `app.js`:

```js
await _loadAllViews();   // ← бросил
applyLang(); loadQualities(); checkSessionMode(); connectWS(); loadAppInfo();  // ← НИЧЕГО не выполнилось
```

Результат у **каждого** скачавшего с гитхаба: сайдбар на месте (он статикой лежит
в `index.html`), контент пустой, версия «v–», WebSocket не открыт. Чёрный экран.
Владелец не воспроизводил никогда — локально все 21 файла на месте.

Два вывода, оба закодированы:

1. **Загрузка фрагментов не имеет права ронять загрузку приложения.** Теперь
   `Promise.allSettled` + фильтр «грузим только то, для чего в ЭТОМ `index.html`
   есть контейнер `#view-<n>`». Отсутствующий фрагмент = один пустой экран, а не
   мёртвое приложение.
2. **Инициализация в `app.js` идёт по шагам через `_bootStep(name, fn)`** — любой
   упавший шаг логируется и не уносит остальные. Правило «оборачивать вызовы из
   чужого файла» касается и `await` в цепочке загрузки, не только обработчиков WS.

Заодно всплыло третье: контейнер `#view-<n>` в зеркале был, а файла нет — то есть
`index.html` зеркала перезаписали локальным. **Синхронизируя зеркало, `index.html`
нельзя копировать целиком** — публичная сборка намеренно беднее (нет
admin/bot/telemetry/guest-*, и там `guest.js`, а не `guest_admin.js`).

## Вырезал блок по границам — проверь баланс тегов (08.08.2026)

Удаление куска разметки скриптом «от якоря A до якоря B» уносит и **закрывающий
тег**, если он попал внутрь диапазона. Так исчез один `</div>`, закрывавший
`field-group`: все последующие панели настроек оказались вложены не туда, и
вкладки по сервисам (Apple, Qobuz, Deezer…) перестали что-либо показывать —
сами кнопки на месте, содержимого нет. Ошибка не видна ни в диффе бегло, ни в
`node --check` (это HTML), ни сканером коллизий.

Дешёвая проверка после любой правки фрагмента:

```bash
python -c "import re,pathlib;s=pathlib.Path('static/views/settings.html').read_text(encoding='utf-8');\
print(len(re.findall(r'<div\b',s))-len(re.findall(r'</div>',s)))"
```

Сравнивать надо **с тем же числом ДО правки** (у нас это стабильная разница 1,
она давняя и безобидная), а не с нулём. И проверять живьём: пройтись по всем
вкладкам и убедиться, что у каждой своя панель непустая.

## Правила

1. **Слил/переименовал файл — удали его из зеркала И убери `<script>`.** Проверять
   оба `index.html`: `static/index.html` и `github_setup/static/index.html`.
2. **Новые глобалы объявлять `var` или через `window.X`**, если имя хоть немного
   общее (`_items`, `_cache`, `_state`). `let` на верхнем уровне — заряженное ружьё.
3. **Правишь JS — подними `?v=`** в обоих `index.html`. Иначе у людей останется
   старый файл и любой вывод будет врать (уже ловили: «русский хардкод» оказался
   устаревшим кэшем).
4. **Перед релизом прогнать сканер** — он ловит коллизии `let/const`, скрипты,
   которых нет на диске, **и** контейнеры `#view-*` без файла фрагмента:

```bash
python tools/check_js_collisions.py
```

## Почему обычная проверка это не ловит

`node --check` проверяет файлы ПООДИНОЧКЕ — коллизия видна только в совокупности
загруженных скриптов, поэтому каждый файл по отдельности «валиден». Ловится либо
сканером выше, либо реальной загрузкой страницы (скилл `ripster-headless-verify`:
слушать `Runtime.exceptionThrown` + `Log.entryAdded` уровня error и требовать
ноль ошибок).

## Защита в коде

Вызовы функций из другого файла в обработчиках WebSocket оборачивать:

```js
if (typeof checkAMDStatus === 'function') checkAMDStatus();
```

Это не лечит причину, но не даёт одному сломанному файлу утащить за собой разбор
события и остальной интерфейс.
