# Тексты песен: где они берутся и где теряются

## Карта: кто и чем отдаёт

| Сервис | Чем добывается | Состояние |
|---|---|---|
| **Apple** | `utils/lyrics` в `main.go` → `amp-api.music.apple.com/v1/catalog/{sf}/songs/{id}/lyrics` | работает (починено 08.08.2026) |
| **Deezer** | deemix, ключи `lyrics` (вшить) и `syncedLyrics` в его конфиге; в `engines/deezer.py` есть `_lyrics_override` | работает |
| **Tidal** | OrpheusDL, `ModuleModes.lyrics` + `get_track_lyrics()` | включено в `orpheus/config/settings.json` |
| **Spotify** | OrpheusDL, тот же механизм | включено там же |
| **Qobuz** | streamrip текстов не умеет | нет |
| **SoundCloud** | у загрузок текстов не бывает | нет |

Общие тумблеры: `config.yaml` → `embed-lrc` (вшить в тег трека) и
`save-lrc-file` (отдельный `.lrc` рядом). OrpheusDL — свои:
`global.lyrics.embed_lyrics` / `save_synced_lyrics`.

## Разрыв №1: текст живёт в магазине ПОДПИСКИ, а не в магазине из ссылки

Apple отдаёт текст только тому магазину, где действует подписка по
`media-user-token`. Ссылка же несёт страну **того, кто ею делился**.

Живой случай 08.08.2026 — трек Kloyd «Saturated», ссылка `/ru/`:

```
ru → HTTP 404  {"title":"No related resources","code":"40403"}
ca → HTTP 200  текст ЕСТЬ          ← магазин нашей учётки
us → HTTP 404
gb → HTTP 404
```

Человек видел текст на телефоне и справедливо не понимал, почему бот молчит.

**Правило:** для текстов перебирать магазины — сначала магазин трека, потом
`apple-country` (что ответила сама Apple при проверке учётки), потом
`storefront` из конфига. `getLyricsAnyStorefront()` в `main.go`. Тот же перекос
был в матрице доступности (`availability.py`) — там чинилось отдельно.

`storefront` в конфиге — это то, что вписал человек, и он запросто расходится с
реальностью: у владельца стояло `us`, а подписка оказалась `ca`. Поэтому
`apple-country` (ответ Apple) в списке идёт РАНЬШЕ конфига.

⚠️ Правка в `main.go` требует **пересборки** `apple-music-downloader.exe` —
`go build -o apple-music-downloader.exe .` в корне. Без пересборки правка не
доезжает никуда, а по логам это неотличимо от «не помогло».

## Разрыв №2: скачали, но не отправили

Бот шлёт файлы **строго по манифесту**, а в манифест попадают только
аудиофайлы. `.lrc` лежали рядом с треками и не уходили никогда — даже когда
человек специально включал тумблер «📝 Текст».

Лечится в `tgbot/bot.py`, функция `_send_track_lyrics()`. Три требования, все
проверены на живом чате:

1. **Текст идёт сразу после СВОЕГО трека, а не одним файлом на релиз.** Первый
   заход отправлял один `.txt` на весь альбом — на 11 треках это не отвечает на
   вопрос «где чей текст». Владелец забраковал сразу и был прав.
2. **Привязан к треку** — `reply_to_message_id` на сообщение с песней.
3. **Свёрнут, раскрывается по нажатию** — `<blockquote expandable>` (Bot API
   7.0+). Без этого лента превращается в простыню. Проверено: Telegram
   возвращает entity `expandable_blockquote`.

```python
html = "<blockquote expandable>" + esc(body) + "</blockquote>"
await bot.send_message(chat_id, html, reply_to_message_id=track_msg_id,
                       disable_notification=True)
```

`_lrc_to_plain()` снимает тайм-коды и служебные теги — читателю они мешают,
плееру нужны только внутри `.lrc`.

Три ловушки, на которых легко обжечься:

- **Лимит 4096 символов.** Превышение отклоняет сообщение ЦЕЛИКОМ — человек
  получит не «обрезанный текст», а ничего. Режем заранее, по границе строки.
- **`m` из предыдущей итерации.** Если обе попытки отправить трек упали,
  переменная с сообщением сохраняет ЧУЖОЙ `message_id`, и текст уходит ответом
  не на ту песню. Сбрасывать в начале каждой итерации.
- **Сообщение-цель могли удалить** — тогда отправляем без привязки, но
  отправляем. Падение текста не должно ронять уже отправленные треки (весь
  вызов в `try`).

## Как диагностировать за минуту

1. **Текст вообще скачался?** Ищи `.lrc` рядом с треком. Нет файла — проблема на
   стороне добычи (разрыв №1). Есть — на стороне доставки (разрыв №2).
2. **В логе `failed to get lyrics`?** Это сообщение раньше выдавалось на ЛЮБУЮ
   причину: нет MUT, не тот магазин, у трека и правда нет текста. Теперь пишем,
   какие магазины спрашивали. Если нужно копнуть — дёрни эндпойнт руками с
   `Authorization: Bearer <authorization-token>` и cookie `media-user-token`, по
   очереди для нескольких магазинов: разные коды ответа сразу покажут причину.
3. **Диск чистится сам** (авто-очистка через N минут) — отсутствие `.lrc` в
   старой папке ничего не доказывает, проверяй на свежей загрузке.

## Добавляя тексты новому сервису

- Спрашивай себя, к чему привязан текст: к треку, к региону или к подписке. У
  Apple — к подписке, и это ловушка по умолчанию.
- Клади рядом с треком `.lrc` — тогда доставка в бот и вшивание в тег заработают
  сами, без правок в боте.
- Сообщение об ошибке обязано различать «текста нет» и «спросили не там» —
  иначе получится очередное «failed to get lyrics» (см. скилл
  `ripster-honest-diagnostics`).

Связано: `ripster-remember-what-you-learned` (откуда взялся `apple-country`),
`release-availability-matrix` (тот же перекос по магазинам),
`ripster-tgbot-infra` (отправка файлов пользователю).
