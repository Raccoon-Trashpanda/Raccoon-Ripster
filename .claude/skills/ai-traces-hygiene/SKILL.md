# Следы генеративных моделей: что чистить, а что не трогать

## Правило номер ноль: вредит ОТГРУЗКА, а не наличие

Метка в референсе, который лежит в `design/` и никуда не уезжает, не вредит
никому. Красным должно становиться только то, что попадает людям:
`github_setup/`, `static/`, `installer/`, вложения в бота, файлы владельцу.

Из этого следует и обратное: **чистить всё подряд не надо.** Массовая перезапись
файлов ради гигиены — это дифф на сотни файлов, потерянные оригиналы и ноль
выгоды. `design/` — мастерская, там метки безопасны и полезны (по ним видно,
чем сделан референс).

## Что было измерено в этом проекте (16.08.2026)

- **10 картинок в `design/`** несут C2PA: обе «утверждённые»
  (`approved/neon-reference-mobile.png`, `neon-reference-desktop.png`), обе
  гроковские и файлы из ChatGPT. Маркеры в байтах: `jumb`, `c2pa`, `caBX`,
  `digitalSourceType`, `trainedAlgorithmicMedia`.
- **В отгружаемое не уезжала ни одна** — в `github_setup/`, `static/`,
  `installer/` помеченных картинок ноль. То есть риск был, а утечки не было.
- **Четыре мягких переноса** нашлись в тексте, и один — в ОТГРУЖАЕМОМ файле
  (`github_setup/.claude/skills/ripster-long-text/SKILL.md`). Это не косметика:
  слово `ДЕЙСТВИ<U+00AD>ТЕЛЬНО` не находится поиском по «ДЕЙСТВИТЕЛЬНО». Убраны.

## Проверка

```bash
python tools/check_ai_traces.py            # 0 — чисто, 1 — есть что чинить
python tools/check_ai_traces.py --selftest # доказать, что проверка умеет краснеть
```

Смотрит СЫРЫЕ БАЙТЫ, а не через библиотеку разбора: так проверка не зависит от
того, установлен ли Pillow или exiftool на машине. `design/` печатается отдельным
разделом «к сведению» и на код возврата не влияет.

**BOM в начале файла уликой не считается** — это законная подпись кодировки, и
без этого исключения проверка вечно краснела бы на `index.html`.

**Детектор не должен содержать искомое ЛИТЕРАЛОМ.** Первая версия проверки
хранила невидимые символы прямо в словаре — и на первом же прогоне нашла сама
себя, отчего «отгружаемое» покраснело на собственном коде проверки. В исходнике
стоят только escape-последовательности (`"\u200b"`), то есть файл целиком в
ASCII, а нужный символ появляется лишь в памяти. Тот же принцип относится к
тестовым фикстурам: делать их из `chr()`/escape, а не вставлять символ.

Запускать перед упаковкой релиза — рядом с `preflight-ripster`, у которого уже
есть гейт на деанон-утечки: это тот же класс, только про происхождение файла.

## Чистка

Инструмент: **[watermarks-remover](https://github.com/guillaumemeyer/watermarks-remover)**
(Python 3.10+, ядро без зависимостей, сети и моделей не требует).

```bash
git clone --depth 1 https://github.com/guillaumemeyer/watermarks-remover
python watermarks-remover/service/scripts/inspect_file.py файл      # что внутри
python watermarks-remover/service/scripts/clean_file.py файл -o чистый
```

Форматы: PNG/JPEG/WebP (C2PA, APP11, XMP), PDF, DOCX/ODT (docProps, generator),
SVG, HTML/Markdown (meta, JSON-LD, YAML-фронтматтер).

**Проверено на нашем файле:** `neon-reference-mobile.png`, 1 729 053 → 1 704 131
байт (снялся чанк `caBX`), повторная проверка даёт `C2PA: False`, а **хеш пикселей
совпал побайтово** — изображение не тронуто. То есть чистка метаданных здесь
без потерь, и бояться её не нужно.

## Чего делать НЕ надо

**Не переписывать текст «чтобы не определялся детектором».** У инструмента есть
второй слой — переписывание локальной моделью, и у него два свойства, которые
делают его неподходящим для нас:

1. Статистические метки живут в ВЫБОРЕ СЛОВ по всему тексту, поэтому снять их
   можно только существенным переписыванием — то есть заменой авторского текста
   на потолок переписывающей модели. Наши хэндоффы и комментарии в коде ценны
   именно формулировками.
2. Автор инструмента честно пишет в README, что **не может гарантировать**, что
   детекторы вендоров не сработают. Работа, результат которой нельзя проверить,
   не должна выдаваться за сделанную.

**Не «перегенерировать» картинки ради снятия скрытых меток.** Перегенерация —
это ДРУГАЯ картинка. Для референса дизайна, по которому принимают вёрстку, это
подмена канона, а не гигиена.

**Не чистить вслепую то, что читает код.** У `index.html` в обоих деревьях BOM
стоит осознанно; у вендоренных файлов (`tools/lucida/**/LICENSE.md`) свои
символы — их трогать не наше дело.

## Как чинить невидимые символы

Точечно и с проверкой, что смысл не поехал: мягкий перенос внутри слова надо не
просто удалить, а СКЛЕИТЬ слово (`ДЕЙСТВИ<SHY>\n  ТЕЛЬНО` → `ДЕЙСТВИТЕЛЬНО`),
иначе на месте улики останется разорванное слово. Правки текстовых файлов —
только `Edit` или `sed`, **никогда `Set-Content`** (15.08.2026 так испортили
кодировку `static/index.html`).

Связано: скиллы `preflight-ripster` (гейт перед сборкой),
`ripster-honest-diagnostics` (почему проверка обязана уметь краснеть).
