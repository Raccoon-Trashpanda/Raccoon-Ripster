# Плеер: два движка, три источника звука

## Главное: движка ДВА, и каждый глушил только себя

`static/js/player.js` играет двумя разными способами, и выбор делается
автоматически:

- **Web Audio** (`_WA.curSource`, буферный источник) — для однодоменных потоков:
  наш прокси `/api/stream/deezer/…`, `/api/library/file`. Включается, когда
  `_waCanPlay(item)` истинно и включён `player-gapless`.
- **Обычный `<audio id="pp-audio">`** — для всего остального: Tidal, Qobuz,
  HLS, DRM.

**Баг 29.07.2026:** трек Tidal играл ПОВЕРХ трека Deezer. Причина: смена
`audio.src` глушит только `<audio>` и ничего не делает с буферным источником
Web Audio, а `_waPlay` останавливал только свой `curSource` и не трогал
`<audio>`. Любой переход МЕЖДУ движками оставлял оба звучать.

**Исправлено** парой симметричных глушилок — `_waStopIfPlaying()` вызывается в
начале обычного пути, `_plainStopIfPlaying()` — в начале `_waPlay`.

> При ЛЮБОЙ правке пути воспроизведения проверяй переход между треками **разных
> движков** (например Deezer → Tidal), а не только соседние треки одного
> сервиса. Внутри одного движка баг не воспроизводится.

## Все источники звука в приложении

1. `pp-audio` — основной `<audio>`;
2. `_WA.curSource` — буферный источник Web Audio (безшовный режим);
3. `Preview._fpsEl` — скрытый `<video>` для FairPlay/SoundCloud DRM (Safari не
   умеет EME на `<audio>`);
4. `bbc-audio` — у BBC свой элемент, намеренно не читается основным плеером;
5. `_floatWin` — плавающее окно через `window.open` (в окне Ripster.exe не
   работает, см. скилл `ripster-webview-shell`).

`_playPreviewAt` уже гасит `_hls` и `_fpsEl` — но исторически не трогал соседний
движок. При добавлении нового источника звука добавляй его во ВСЕ пути
остановки, иначе получишь ту же одновременность.

## Защита от гонок, которая там уже есть

`Preview._playGen` — счётчик поколений. Разрешение потока асинхронно, и если
пользователь закрыл плеер или переключил трек ВО ВРЕМЯ ожидания, старый вызов
всё равно доходил до `play()` («закрыл плеер, а Tidal играет»). Каждый старт
увеличивает счётчик, после каждого `await` проверяется, не устарело ли поколение.
Не убирай эти проверки при рефакторе.

## Что ещё стоит помнить

- `_waStartKeepalive` держит аудиосессию живой, чтобы `AudioContext.resume()`
  работал после блокировки экрана; на мобильных Web Audio принудительно
  отключается — фоновая вкладка убивает контекст, а голый `<audio>` выживает.
- Позиция длинных миксов сохраняется (`_mixPosGet`), автоперемотка предлагается
  только для дорожек длиннее 10 минут — иначе обычный трек молча начинался бы
  с середины.
