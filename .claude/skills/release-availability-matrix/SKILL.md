# Где релиз УЖЕ можно скачать (а не где он «вышел»)

## Суть проблемы

Мировая дата релиза — фикция. Лейбл ставит дату, но каждая витрина наполняется
сама, в своей зоне и в своём темпе. Плюс аккаунты владельца **живут в разных
странах**: Tidal новозеландский, Apple американский, Deezer европейский.
В результате в пятницу утром картина обычно такая:

| Сервис | Состояние |
|---|---|
| Spotify (NZ-время уже наступило) | релиз есть |
| Deezer | есть |
| Apple (US) | ещё нет |
| Qobuz | появится позже, иногда на сутки |

**Отсюда правило: «релиз вышел» — бесполезное утверждение. Значение имеет только
«в каком сервисе я могу скачать его прямо сейчас».**

## Что делать неправильно

- **Ставить в очередь по дате релиза.** Дата говорит, что релиз анонсирован, а не
  что файл отдаётся. Задача упадёт или, хуже, тихо потеряется.
- **Считать отсутствие в одном сервисе ошибкой.** «Не найдено в Apple» в день
  выхода — норма, а не сбой. Писать в лог как ошибку значит приучить владельца
  игнорировать логи.
- **Гнать ссылку одного сервиса в движок другого.** Ссылка Spotify, отданная
  Apple-загрузчику, даёт «Failed to get album» и exit 0 — успех на вид, пустота по
  факту (реальный случай 2026-07-27).

## Модель: матрица доступности

Для каждого релиза держим не «есть/нет», а **состояние по каждому сервису**:

```
{
  "upc": "5039060846896",
  "services": {
    "spotify": {"available": true,  "url": "...", "checked": "2026-07-27T09:00"},
    "deezer":  {"available": true,  "url": "...", "checked": "..."},
    "apple":   {"available": false, "reason": "not_in_catalog_yet"},
    "qobuz":   {"available": false, "reason": "not_in_catalog_yet"},
    "tidal":   {"available": false, "reason": "no_token"}
  }
}
```

Причина важна не меньше факта — она различает три разные ситуации:

- `not_in_catalog_yet` — витрина ещё не наполнилась, надо перепроверить позже;
- `region_locked` — в сторефронте этого аккаунта релиза не будет вовсе;
- `no_token` / `no_subscription` — наша проблема, а не витрины, чинится настройками.

## Как проверять доступность

Только **точным идентификатором**, никогда по названию: одноимённые синглы,
делюксы и ремастеры дают ложные совпадения.

- **UPC (штрихкод)** — идентичность релиза. Apple: `filter[upc]`; Deezer:
  `album/upc:<upc>`.
- **ISRC первого трека** — там, где поиска по штрихкоду нет (Qobuz, Tidal): находим
  запись, от неё поднимаемся к альбому.

Проверка должна быть **дешёвой и повторяемой**: результат кэшируется вместе с
временем, недоступные сервисы перепроверяются по расписанию, доступные — нет.

## Как показывать владельцу

Не «релиз доступен», а **где именно**:

```
Above & Beyond — Flow State (2026-07-27)
  ✅ Spotify · ✅ Deezer — можно скачать
  ⏳ Apple, Qobuz — ещё не появился, проверю позже
```

Кнопка скачивания предлагает **только те сервисы, где `available: true`**, и
качество показывается по тому, что реально даёт этот сервис. Когда релиз
появляется в очередном сервисе — кнопка просто добавляется, без уведомления
«вышло» (оно уже было).

## Авто-скачивание

Скачивать **как только появилось хоть где-то**, а не ждать «своего» сервиса —
иначе релиз можно прождать сутки. При этом уважать предпочтения по качеству:
если владелец хочет ALAC, а сейчас доступен только Spotify (откуда качать
нельзя) — ждать; если доступен Deezer с FLAC — брать оттуда.

Порядок предпочтения задаётся владельцем и обычно выглядит как
«Apple ALAC → Qobuz Hi-Res → Deezer FLAC → Tidal», а фактический выбор —
пересечение этого списка с матрицей доступности.

## Часовые пояса аккаунтов

Держать в конфиге, какой стороны каждый аккаунт: `tidal-country: NZ`,
`storefront: us` и т.д. Это нужно для двух вещей:

1. **Когда проверять.** Новая Зеландия входит в пятницу раньше всех — проверка,
   выровненная на окленДскую полночь, ловит релизы на полсуток раньше
   (`next_check_delay()` в вишлисте уже это делает).
2. **Чего ждать.** Если аккаунт американский, релиз с европейским эксклюзивом там
   не появится никогда — это `region_locked`, а не «ещё не подъехал», и
   перепроверять его бессмысленно.

## Проверка перед сдачей работы

- релиз, доступный только в Spotify, **не** ставится в очередь как Apple-задача;
- недоступность показана как ожидание, а не как ошибка;
- при появлении в новом сервисе кнопка добавляется без дубля уведомления;
- матрица переживает перезапуск (кэш на диске, не в памяти);
- `region_locked` не перепроверяется бесконечно.

## Следить и качать — разные оси (31.07.2026)

У подписки вишлиста поле `service` означает **куда качать**, а не где следить.
Наблюдение всегда идёт по каталогу Apple (`itunes.apple.com/lookup`, без токена),
и это единственная ось, по которой список опрашивается целиком.

Пока в `_check_watchlist()` стоял фильтр `service == "apple"`, запись на любом
другом сервисе не попадала **ни в один** список опроса: не Apple, не SoundCloud,
не лейбл. Она молча жила с `artist_id: ""` и `last_check: null`, а `POST
/api/watchlist` в ответе рапортовал `resolved: true` — потому что признаком
пригодности считалось «service != apple». Ровно тот же силуэт, что и слепота
24.07: список выглядит полным, опрашивается его часть.

Что проверять при любой правке этого места:

- каждая запись, кроме лейбла и SoundCloud, имеет `artist_id` — иначе она мертва;
- дедуп по `artist_id` учитывает **сервис**: один артист на Apple и на Deezer —
  две разные подписки, общий ключ удалил бы одну;
- найденный релиз проходит через `_pick_download_url()` — предпочтение отдаётся
  сервису подписки, но если там его ещё нет, берётся уже имеющаяся Apple-ссылка.
  Потерять релиз хуже, чем скачать его не из любимого сервиса.

### Ловушка перевода релиза в другой сервис

`_match_seeds_in_service()` (discovery.py) переводит найденный релиз в целевой
сервис двумя путями: точным (штрихкод/ISRC) и поиском по названию. У Deezer и
Spotify ветки поиска по названию не было вообще — `else: continue`, — а
`_seed_upc()` умеет доставать штрихкод только из самих Deezer/Spotify. Значит
релиз, найденный в Apple, в Deezer не переводился **никогда**, хотя
`_search_deezer()` лежал рядом и работал. Подписка «качать из Deezer» тихо
уходила в запасной вариант.

Проверять живьём, а не по коду: взять реальный релиз и прогнать
`_pick_download_url()` по всем сервисам — каждый должен вернуть ссылку своего
домена, а не пусто.
