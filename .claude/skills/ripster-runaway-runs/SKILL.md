# Прогон, который обречён, обязан прекращаться

За сутки 08–09.08.2026 этот класс всплыл **четыре раза** в разных местах, и
каждый раз выглядел по-новому. Общее одно: код честно делал бессмысленную
работу, потому что никто не сказал ему, когда остановиться.

| Где | Симптом | Цена |
|---|---|---|
| Apple, публичный пул | 553 строки «no healthy and ready» | 19 минут, 0 файлов |
| Beatport, чарт | 87 отказов «do not have permission» | 20 минут, 0 файлов |
| Интерфейс, любой запрос | кнопка вечно в «ищу…» | бесконечно |
| Раннер | та же ошибка повторяется 3 раза | ×3 ко всему выше |

## Правило

Отсечка состоит из ДВУХ частей, и вторая обязательна:

```python
if fails >= LIMIT and nothing_succeeded:
    self.abort_reason = "…почему и что делать…"
```

Без второй части отсечка убьёт наполовину рабочую загрузку: отдельные треки
недоступны в регионе всегда, это норма. Условие «ноль успехов» отличает
«здесь ничего не выйдет» от «пара треков не вышла».

Механизм в проекте уже есть: движок ставит `self.abort_reason`, а
`ProcessRunner._engine_wants_abort()` читает его после каждой строки и глушит
процесс. Отдельное событие заводить не нужно.

## 🔴 Ловушка №1: «ноль успехов» — не то, что кажется

Beatport печатает `Downloading track file` **безусловно, прямо перед отказом**.
Счётчик «сохранённых» рос вместе с отказами и глушил защиту — первый боевой
прогон дал 12 отказов и ни одного обрыва.

Считай **попытки** и требуй, чтобы каждая закончилась отказом:

```python
if re.search(r'Downloading track file|Saving\s*:', clean, re.I):
    self._attempts += 1
if "do not have permission" in clean.lower():
    self._perm_fails += 1
    if self._perm_fails >= LIMIT and self._perm_fails >= self._attempts:
        ...
```

Об этой ловушке было **написано в том же файле**, в комментарии к `is_finished`.
Прочитал и всё равно наступил. Читай комментарии рядом с местом правки.

## 🔴 Ловушка №2: диагноз есть, но приходит слишком поздно

Движок Beatport **распознавал** отказ по правам правильно и выдавал внятное
сообщение — но в `is_finished`, то есть после того, как отвалятся все 87 треков.
Правильный диагноз в неправильный момент бесполезен.

Проверяй не только «есть ли обработка», но и **когда** она срабатывает: в
`iter_events` (по ходу) или в `is_finished` (в конце).

## 🔴 Ловушка №3: обрыв без глушения повторов

Отсечка работала, а раннер всё равно повторял задачу трижды — вместо одной
понятной ошибки человек получал три. Отказ по правам/подписке/региону
**постоянен**: повтор нужен для случайных сбоев.

Добавь формулировку в `_RE_NO_RETRY` (ripster/runner.py) — там уже лежат
протухший ARL, гео-блок, отсутствие движка. Проверь обе стороны:

```python
assert     _RE_NO_RETRY.search("отказал в правах")      # глушится
assert not _RE_NO_RETRY.search("сеть отвалилась")       # повторяется
```

## 🔴 Ловушка №4: запрос без таймаута

`api()` в static/js/app.js использовал голый `fetch`. Если сервер завис или
соединение застряло (процесс жив, слушающий сокет мёртв — ловили дважды),
обещание **не завершается никогда**: ни `then`, ни `catch`.

Самое коварное — обработчик ошибки при этом ИСПРАВЕН. Он просто не вызывается,
и по коду всё выглядит правильно. Теперь там `AbortController` на 90 секунд.

**Любая операция обязана заканчиваться результатом или ошибкой.** Если
пользователь видит «ищу…» дольше минуты — ищи отсутствующий таймаут, а не
логику поиска.

## Как проверять отсечку

На НАСТОЯЩИХ строках из `logs/console.log`, а не на выдуманных:

```python
real = [l for l in open("logs/console.log", encoding="utf-8", errors="replace")
        if "do not have permission" in l]
e = Engine(); fired = None
for i, line in enumerate(real, 1):
    list(e.iter_events(line, progress=(0, 0)))
    if e.abort_reason and fired is None: fired = i
print(f"обрыв на строке {fired} из {len(real)}")
```

Такой прогон поймал у меня опечатку в имени константы (`_RE_DONE_TRACK` вместо
`_RE_TRACK_DONE`) — на выдуманных строках она бы не всплыла.

И обязательно обратный случай: при уже сохранённом треке отсечка должна
**молчать**.

Связано: [[ripster-honest-diagnostics]] (там про то, как врёт сам прибор),
скилл `ripster-apple-wrapper` (пустой публичный пул).
