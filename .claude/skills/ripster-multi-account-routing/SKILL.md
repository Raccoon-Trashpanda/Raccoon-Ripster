# Несколько учёток: знать, поднять, закрепить

09.08.2026 альбом Apparat не скачивался сутки. Гипотез было три, все
правдоподобные, и все неверные: «нет в каталоге», «нет прав в регионе», «мы
сами злим serveo». Настоящих причин оказалось три ДРУГИХ, и каждая
вскрывалась только после устранения предыдущей.

## Три причины, которые прятались за одним сообщением

**1. Слот выключен — а мы этого не знаем.**
Сборщик простоя гасит контейнеры через 5 минут. Порт расшифровки перестаёт
слушать, Go пишет `dial tcp 127.0.0.1:10021: connection refused` — и эта строка
тонет среди шестидесяти других, а наружу выходит «нет прав в регионе».

> `connection refused` ≠ «нет прав». Права были. Не было живой сессии.

**2. Пул выдаёт ЛЮБОЙ свободный слот, а не подобранный по стране.**
Маршрутизатор честно выбирал британскую сессию, а `acquire()` возвращал первую
свободную — канадскую. Вся работа по подбору пропадала.

**3. Раздача треков по пулу перебивает закрепление.**
При `apple-parallel-tracks` Go получает ВСЕ порты пула и разбрасывает треки по
контейнерам разных стран. Закреплённый британский слот дал 10 отказов, хотя в
одиночку брал альбом целиком.

## Что теперь есть в проекте

`ripster/apple_accounts.py`:
- `container_storefront()` — страна сессии, спрос порта 30020 **изнутри**
  контейнера (`docker exec` + bash `/dev/tcp`; curl/wget в образе нет).
  Пересоздавать контейнер ради публикации порта нельзя — жжёт слот устройства.
- память стран **на диске** (`dist/docker/slot_countries.json`): выключенный
  слот спросить нельзя, но страна не меняется.
- `ensure_slot_up(container, port)` — поднимает и **ждёт порт**, а не факт
  запуска. Ткнувшийся раньше времени загрузчик получит `connection refused`.
- `pick_slot_for(countries, exclude)` — `exclude` обязателен: «релиз числится в
  витрине» и «наш аккаунт там получит ключ» — разные утверждения.

`ripster/deezer_accounts.py` — то же для ARL: страна, тариф, lossless, срок.
🔒 ARL в кэш не пишется, только хеш: файл попадает в бэкапы.

В `runner.py`: `task["_force_slot"]` закрепляет слот за задачей, и при
закреплении **отключается** раздача по пулу.

## Правила

1. **Идентичности — по АККАУНТУ, а не по номеру слота.** Каталоги
   `dist/docker/rootfs_id/<аккаунт>/data`. При привязке к номеру любая
   перестановка сажает два аккаунта на одну identity → device-limit. Поэтому и
   ручка `POST /api/wrapper/accounts/order` безопасна.
2. **Перестановка аккаунтов — только после переноса каталогов.** Сначала
   мигрировать при ТЕКУЩЕМ порядке, потом менять порядок. Иначе identity уедут
   не к своим владельцам.
3. **У Apple свой ID альбома в каждой витрине.** `ru/gb → 1850997297`,
   `ca/us → 1852529754`, `jp → 1878218670`. Смена страны в ссылке без смены
   номера промахивается мимо существующего релиза — для этого есть
   `apple_router.rewrite_storefront_resolved()`. Для видео ID глобальный.
4. **Спрашивай каталог по НАЗВАНИЮ, а не по ID.** Проверка «один ID по всем
   витринам» врёт: 404 значит «в этой витрине другой номер», а не «недоступно».
   `errors.apple_album_by_storefront()` ищет по имени и возвращает {страна: id}.
5. **Открытый iTunes API, а не amp-api.** У последнего нужен `dev_token`,
   живущий 5 минут — диагностика, протухающая сама, хуже отсутствующей.

## Как проверять

Воспроизводи **полную** ситуацию: погаси слоты, сотри файлы, поставь задачу.
Проверка на уже поднятых контейнерах ничего не докажет.

```bash
docker stop rip-wrapper-1 rip-wrapper-2
find "<downloads>" -ipath "*<альбом>*" -type d -exec rm -rf {} +
# поставить задачу и ждать
docker ps --format "{{.Names}}" | grep -c "rip-wrapper-[12]"   # поднялись сами?
```

И считай ФАЙЛЫ на диске, а не строки в логе. Учти: у сервисов разные корни
(`alac-hires` против `ALAC (Lossless)`) — я дважды считал «3 из 11», глядя не в
ту папку.
